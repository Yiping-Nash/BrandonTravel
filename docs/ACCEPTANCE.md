# Acceptance — 三天演示闭环

## 必须有证据的 E2E（可脚本或浏览器）
1. 从首页创建一个 Trip，填目的地与日期；刷新后可读回。
2. 手动添加 Idea + 不绑定 POI 的自定义活动；刷新不丢。
3. 搜索真实 POI，将地点保存成 Idea（未配置 API Key 时显示阻塞，不伪造真实数据）。
4. 从 Ideas 采纳到指定日期 Itinerary。
5. 在 Kanban 跨日期移动、重排序；切到 Day/Week 后状态与时间一致；反向在 Day/Week 修改日期/时间，回到 Kanban 保持同步；页面刷新仍一致。
6. 不带时间的活动仍可在当天查看，绝不显示成已确定的虚构时间。
7. 在 Trip Chat 问「第一天是不是太满？」：Brandon 读取**最新** Activity，再作解释；能明确区分已知规则和未验证判断。
8. 触发一次真实地点/研究工具调用，并返回结构化 Suggestion；用户确认后保存 Ideas（或指定日期的活动）；不确认时不得改动。
9. 有一次可查 LangSmith Trace，显示模型、工具、关键执行步骤；密钥/敏感数据不泄露。
10. README 写清运行方式、配置、哪些能力为真实调用、哪些仍为 mock/未实现；提供短演示记录与已知限制。

## 质量门槛
- 测试：域 CRUD、跨视图编辑映射、未确认建议不写入、Agent 输出 schema、基本 API 错误态；至少一个自动化浏览器 E2E。
- 人工：桌面浏览器实测交互顺滑、界面无严重溢出；第三方图片/品牌不可直接复制。
- 禁止仅凭截图、模拟 Agent 文字或单独模块能跑就宣布完成。

## 分级交付（出现阻塞时）
- A 级：完整 10 条，真实 POI + Agent + Trace + UI 一体化。
- B 级：Workspace 三视图与持久化、真实 Agent Trip 阅读/建议完成，但部分 POI/地图受 Key 或配额阻塞（公开已知问题）。
- C 级：仅前端模拟与 Agent 分离，不可自称完整 AI 原生 MVP。必须明确标注。
