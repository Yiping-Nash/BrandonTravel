# UX Spec — 开发可执行的交互基线

## 布局
主参照 Mindtrip：一个 Trip 的左侧（可收起）聊天区 + 右侧可切换工作区。宽屏允许展开 Itinerary 以充分展示一周网格；导航简洁，不照搬 Mindtrip 全部商业功能。地图可作为 Explore/活动详情的右侧或抽屉辅助区；三栏不能挤压周视图。

## 页面 / 视角
- 首页：创建/进入 Trip、Explore/本地推荐。无需聊天框也能完成入口任务。
- Trip Workspace：`Ideas | Itinerary | Explore` 为核心标签；`Preferences` 可作为设置页；Bookings/Media 暂不做独立完整模块。
- **Itinerary 内层**：`Board | Day | Week` 视角切换，统一选中日期、日期导航和活动身份。Board 由 Kibo UI Kanban 实现、按日期横向分列，另有未安排候选区；Day/Week 由 yassir-jeraidi/full-calendar 实现。周视图是七天，活动多于七天时有连续日期导航。
- Ideas：可视化候选（用户创建、POI 或 Agent 产生），保存及加入指定日期。不要把 Idea 与时间轴事件混为一谈。
- Explore：搜索框 + POI 结果 + 地图/地点详情。POI 来源、可用能力与限制明确。
- Chat：围绕 Trip 的多轮对话；Agent 的回答可包含结构化建议卡片与「保存到 Ideas」操作，需用户明确触发。历史聊天不是权威 Trip State。

## 活动编辑语义
- 看板拖拽更改日期/顺序；Day/Week 的事件拖拽更改时间。两个组件通过统一 Workspace 命令/API 改状态，禁止各自维护孤立的权威存储。
- 无起止时间的活动在 Day/Week 的全天候选/未定安排区展示，不在小时刻度里伪装为已确定。
- 活动可以是已确认地点的 POI，也可以是自由文本（吃饭、火车、自由活动）。
- 点击活动出现统一详情面板，支持修改时间/日期、地点和备注。拖拽更新失败必须恢复视图并显示错误。
- 建议卡片与 Idea 被采纳之后要可追溯；用户不采纳不改写计划。

## 视觉与可访问性
- 参考 Mindtrip 的克制留白、轻量卡片、流畅侧栏；保留自己的品牌，不要求像素级仿制。
- 直接集成已选 Kibo UI / Full Calendar 基础样式，不先做 Figma 全套高保真。以浏览器运行截图和实际交互作为动态 Hi-Fi 原型。
- 优先 PC 宽屏；窄屏至少不崩溃，侧栏可收起；重要按钮有文本或提示，拖拽之外仍有菜单可操作。

## 初次视觉验收
用一趟包含 5 天、10+ 个活动、3 个 Idea、2 个带时间事件的演示 Trip，展示三视图切换、Ideas 采纳、Chat 与地点搜索。不要在界面上为未实现功能摆放无法操作的按钮。
