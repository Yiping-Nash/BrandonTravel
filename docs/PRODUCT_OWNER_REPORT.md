# Portfolio 1.0 — Product Owner Report

2026-10-26。工程交付版；最终产品及推荐质量签收由 Product Owner / Advisor 完成，状态 **Pending**。

BrandonTravel 已从基础工作台扩展为可持续编辑的 AI 旅行规划工作区。用户可以从空白开始，逐步补充 Where / When / Who，与 AI 建立多日初稿，在三个视图中细化，再研究有证据的候选。AI 产生的是待确认方案，正式安排始终由用户决定。

| 痛点 | 当前可用功能 | 验证边界 |
|---|---|---|
| 从空白构思多日旅行 | 可选目的地、日期与同行人；AI 蓝图；逐项 Diff；确认后原子保存；继续手动编辑 | 山西古建、杭州亲子、上海长者三类真实浏览器蓝图路径通过。杭州首次模型格式错误被拒绝，显式重试后通过，失败保留。 |
| 单日计划缺乏空间与时间联系 | Chat / Timeline / 高德地图同屏；共享活动与选中日期；AI 时间调整；重叠、未知时段、远距离及移动间隔提示 | 山西真实单日调整通过。实际地图已加载；路线仅是高德驾车参考，未知中间地点不生成完整车程。 |
| 推荐无法判断依据及适合程度 | Main → Research 委派；高德与权威网页；候选、取舍、来源和未知项；保存 Ideas 或指定日期；刷新恢复 | 山西双林寺、杭州中国丝绸博物馆、上海邮政博物馆均通过真实研究与采纳闭环。均为 partial，并列明开放/预约等未知项；上海摘要仍有过于肯定的表述，需人工复核，详见工程证据。 |

体验保留现有 Board / Day / Week 组件，采用简洁的白色工作区。无日期时不会捏造日历；研究运行中可以继续编辑；取消、刷新恢复、过期方案、重复采纳、上游失败均有明确边界。已确认后列表刷新失败会显示“已保存”，不会误导成未写入。证据默认显示可读摘要，内部 JSON 和哈希只在技术详情中展开。

**质量与限制。** 自动测试证明数据契约、权限与状态边界，不证明每条推荐正确。真实运行曾出现无效 JSON、字段层级错误及早期上下文限制；没有隐藏失败或悄悄回退为 mock。模型仍可能提出不够合理的时间、重复或过于肯定的推荐；开放日、未来票务和交通方式需要用户核实。正式人工质量评分未完成。地图为可缩放、可定位的真实静态底图，最多十个标记；连续导航通过高德链接完成。

当前面向本地单用户演示，不含生产认证、多人协作、预订支付、跨午夜活动或小红书采集。严格内容哈希会让内容修改前的其他待采纳研究候选过期，需要重新研究。这一保守取舍保证不会用旧方案覆盖新安排。英文/中文 README、Hero、三个真实短 Demo、学习指南和审查记录已纳入作品集材料；主分支尚未发布。

**评审入口。** 按 [Demo 路径](PORTFOLIO_DEMO.md)亲自创建旅行，查看 [真实测试与失败样本](PORTFOLIO_EVIDENCE.md)、[作者学习指南](agent-learning/portfolio-guide.md)。优先评审三个问题：蓝图是否连贯；单日建议是否真正帮助取舍；证据是否充分支持推荐理由。不得将 Codex 的检查结论当作真人签收。
